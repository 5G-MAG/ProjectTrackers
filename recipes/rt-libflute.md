## rt-libflute
**What it implements:** C++17 library for the FLUTE/ALC protocol (File Delivery over Unidirectional Transport), CMake target `flute`, project version 0.12.4, Linux only (needs libnl-3.0) [AGENTS.md] [CMakeLists.txt]. The README names no 3GPP function or specification. Source comments cite 3GPP TS 26.346 (FDT namespaces) and TS 26.517 (SSM source filter), plus RFC 3926, 4607, 5052 [src/FileDeliveryTable.cpp] [src/Receiver.cpp] [src/File.cpp].
**Language and build system:** C++17, CMake 3.16 minimum, Ninja generator, clang-tidy runs during compilation (`set(CMAKE_CXX_CLANG_TIDY clang-tidy)`) [CMakeLists.txt] [AGENTS.md]. Debug flags `-Wall -Wextra -Werror -g3`, Release `-Wall -O3` [CMakeLists.txt]. Needs Boost, spdlog, OpenSSL, tinyxml2, libnl-3.0, libconfig++, zlib [CMakeLists.txt]. No minimum compiler version stated; CI installs g++-12 [.github/workflows/unit-tests.yml].
**Build:** Dependencies first (CI, Ubuntu): `sudo apt-get install -y --no-install-recommends ninja-build build-essential cmake libboost-all-dev libspdlog-dev libtinyxml2-dev libconfig++-dev libssl-dev libnl-3-dev zlib1g-dev ccache clang-tidy clang g++-12` [.github/workflows/unit-tests.yml].
- CI and AGENTS.md: `cmake -S . -B build -GNinja -DBUILD_TESTING=ON -DCMAKE_BUILD_TYPE=Release` then `cmake --build build --parallel` [AGENTS.md] [.github/workflows/unit-tests.yml]. Switches: `-DBUILD_TESTING=OFF`, `-DBUILD_EXAMPLES=OFF` [AGENTS.md].
- README variant: `cd rt-libflute/`, `mkdir build && cd build`, `cmake -GNinja ..`, `ninja` [README.md]. Configure with tests on needs network: GoogleTest v1.17.0 comes from FetchContent [tests/CMakeLists.txt].
**Run the unit tests:** Framework GoogleTest, folder `tests/`, unit sources `tests/test_transmitter.cpp`, binary `build/tests/flute_unit_tests` [AGENTS.md] [tests/CMakeLists.txt].
- All unit tests (CI): `ctest --test-dir build/tests -R '^unit:' --output-on-failure -j 2` [.github/workflows/unit-tests.yml]. README: `cd build/tests` then `ctest -R '^unit:'` [README.md].
- One test: `ctest --test-dir build/tests -R "RateLimitGetterSetter"` or `./build/tests/flute_unit_tests --gtest_filter="TransmitterGetterSetterTest.RateLimitGetterSetter"` [AGENTS.md]. List: `ctest --test-dir build/tests -N`, `./build/tests/flute_unit_tests --gtest_list_tests` [AGENTS.md].
- Five tests, all on `Transmitter` only (rate limit, endpoint setters, UDP tunnel address, deferred deactivation) [tests/test_transmitter.cpp].
**Run it locally:** No daemon and no config file; two demo apps in `build/examples` (`flute-receiver`, `flute-transmitter`) configured by command line only (argp) [README.md] [examples/flute-receiver.cpp]. Defaults: multicast 238.1.1.95, port 40085, TSI 16, log level 2 [examples/flute-transmitter.cpp].
- Receiver: `cd rt-libflute/build/examples`, `./flute-receiver`, help `./flute-receiver --help`, output dir `./flute-receiver -o /path/to/output/directory` [README.md]. Options -i -m -p -k -l -T -o [examples/flute-receiver.cpp].
- Transmitter: `./flute-transmitter -r 100000 file` (-r is kbit/s; do not exceed what the network allows) [README.md]. Options -m -p -t -r -k -l -g -T -n -R -e [examples/flute-transmitter.cpp].
- IPSec (optional, AES 256-bit key as 64 hex characters): `sudo ./flute-receiver -k <key>`, `sudo ./flute-transmitter -r 100000 -k <key> file`, inspect with `sudo ip xfrm state list` and `sudo ip xfrm policy list`; no-sudo alternative `sudo setcap 'cap_net_admin=eip' ./flute-transmitter` (same for the receiver) [README.md].
**Exercise a feature end to end:** Manual: start the receiver, then the transmitter with a file, as above; on one machine the receiver overwrites the file at its original path unless `-o` is given [README.md].
- Automated: `ctest --test-dir build/tests -R '^e2e:' --output-on-failure --verbose -j 1` (CI) or `ctest -R '^e2e:' --verbose` in `build/tests` [.github/workflows/e2e-tests.yml] [README.md]. One test: `./build/tests/flute_e2e_tests --gtest_filter="FluteEndToEndTest.TransmitsFileToReceiver"` [AGENTS.md].
- What it does: in one process a `Receiver` and a `Transmitter` use 239.255.0.1:18091, TSI 4242, MTU 1400, send a 5,000-byte A-Z payload, wait up to 5 s, then assert TOI, content location, length and bytes. `...ThroughUdpTunnel` adds a bridge thread on 127.0.0.1:18092 that checks inner IPv4/UDP headers and checksums and forwards the FLUTE payload [tests/test_end_to_end.cpp].
**Fixtures, mocks and sample data:** None on disk. Payload and the tunnel bridge are built in code in `tests/test_end_to_end.cpp`; the examples send any file you name. `utils/base64.*` is third-party code [NOTICE].
**Logs and how to see that it worked:** The demos log through an spdlog syslog logger with LOG_PERROR, level set by `-l` (0 trace to 6 none, default 2) [examples/flute-receiver.cpp]. Success lines: receiver `FLUTE receiver demo starting up` then `<file> (TOI <n>) has been received`; transmitter `Queued <file> ... for transmission, TOI is <n>` then `<file> (TOI <n>) has been transmitted` [examples/flute-receiver.cpp] [examples/flute-transmitter.cpp]. In the e2e test stdout shows `Received file TOI ...` and `Transmitted file TOI ...`; success is a passing ctest [tests/test_end_to_end.cpp].
**Conventions for contributors:** AGENTS.md rules [AGENTS.md]: classes PascalCase, public methods snake_case, private methods and members `_snake_case`, struct fields snake_case, type aliases `_t`; `#pragma once` only; namespace `LibFlute` (nested `LibFlute::IpSec`); headers use normal return types, `.cpp` files use trailing `auto f() -> T`; 2 spaces, K&R braces, Google format (no `.clang-format`); library errors historically `throw "string literal"`, follow local pattern; logging with spdlog; catch by const reference; smart pointers, no new raw `new`/`delete` for ownership; every file starts with the 15-line 5G-MAG licence header; public API uses Doxygen `@param`/`@return`; unfinished work marked `// [TODO]`; shared state guarded by `std::lock_guard<std::mutex>`. PRs: unit and e2e workflows run on `pull_request` to `development` [.github/workflows/unit-tests.yml]; Doxygen pages deploy on push to `main` [.github/workflows/main.yml]. No CONTRIBUTING.md or CLAUDE.md; issue templates in `.github/ISSUE_TEMPLATE/`.
