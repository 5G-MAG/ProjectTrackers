## rt-mbs-examples
**What it implements:** Not one network function. A collection of examples and test tooling for 5G Multicast Broadcast Services (MBS): a Docker Compose 5G system (Open5GS 5GC with MB-SMF, MB-UPF and MBS-enhanced AMF, srsRAN MBS gNB and UE, Test AF/AS, optional MBSF and MBSTF), Python API tests for the MBSF and MB-SMF service APIs, a mock media server, Insomnia collections, tmux start scripts [CLAUDE.md] [README.md] [mbs-docker-setup/README.md]. No 3GPP TS number is stated in the READMEs; API names seen are `nmbsmf-tmgi`, `nmbsmf-mbssession`, `nmbsf-mbs-us`, `nmbsf-mbs-ud-ingest` [test/README.md] [test/test_mbsf_crud.py].
**Language and build system:** Python (pytest, unittest, httpcore with h2), Node.js Express (`node:18-alpine` in the image), Bash, Docker buildx bake (`docker-bake.hcl`) and Compose. No top-level build; no minimum versions stated except the image pins in `mbs-docker-setup/.env`: 5G-MAG MBS 0.1.4, MBSTF v1.4.0, MBSF v1.1.0, Open5GS v2.7.7, MongoDB 8.0 [mbs-docker-setup/.env] [express-mock-media-server/docker/Dockerfile].
**Build:** Docker images (skip if you pull from ghcr.io): needs the docker buildx and compose plugins; `export GITHUB_USER=your_github_username`, `export GITHUB_TOKEN=your_personal_access_token` (PAT with `read:packages`), then `cd mbs-docker-setup` and `docker buildx bake` [mbs-docker-setup/README.md]. Mock server: `cd express-mock-media-server`, `npm install` [express-mock-media-server/Readme.md]. Tests: `cd test`, `python3 -m venv .venv`, `source .venv/bin/activate`, `pip install -r requirements.txt` [test/README.md]. tmux scripts need sibling checkouts of `open5gs`, `rt-mbs-function`, `rt-mbs-transport-function` built locally; no build steps here [CLAUDE.md].
**Run the unit tests:** There are no unit tests and no CI (no `.github` folder). The tests in `test/` are API tests against running NFs. From `test/` with the venv: `pytest -v -s test_mbsf_crud.py` (pytest); one test: `pytest -v -s test_mbsf_crud.py::test_user_service_crud`; MB-SMF suites: `python3 tests.py` (unittest, run from `test/` because paths are relative) [test/README.md] [CLAUDE.md] [test/tests.py]. A command for one unittest case is not found in the repository.
**Run it locally:** Docker (from `mbs-docker-setup`): set `DOCKER_HOST_IP=<your_host_ip_address>` in `.env`, then `docker volume create open5gs_db_data` and `docker volume create open5gs_db_config` (once), then `docker compose -f compose-files/internal/docker-compose-mbs.yml --env-file=.env up -d`; stop with the same command ending `down` [mbs-docker-setup/README.md].
- With MBSF and MBSTF instead (only one deployment at a time, same container names): `docker compose -f compose-files/internal/docker-compose-mbs-user-services.yml --env-file=.env up -d`; it adds `mbstf` and `mbsf` and mounts `upf_mb-upf-tunnel.yaml` [mbs-docker-setup/README.md] [mbs-docker-setup/compose-files/internal/docker-compose-mbs-user-services.yml].
- Network `5g-mag` (bridge `br-5g-mag`, 10.33.33.0/24); only the Open5GS web UI is published on host port 9999; `mongo:${MONGODB_VERSION}` runs as `db`; MB-UPF, gNB, UE are `privileged` [mbs-docker-setup/compose-files/internal/docker-compose-mbs.yml]. Optional monitor on http://localhost:3002: set `COMMON_SHARED_PATH` in `.env`, clone `rt-common-shared`, run `docker compose -f /absolute/path/to/rt-common-shared/docker-monitor/docker-compose-monitor.yml --env-file=.env up -d` after the MBS stack is up [mbs-docker-setup/README.md].
- Mock media server: `cd express-mock-media-server`, `npm start` (port 3004, or `PORT=... npm start`); Docker: `cd docker && docker compose up --build` [express-mock-media-server/Readme.md] [CLAUDE.md]. Served from `public/`: `/object1` direct; `/object2` 302 to `/real-object2`; `/object3` 301 to `/perm-object3` 302 to `/real-object3`; `/object4` 302 to `/temp-object4` 301 to `/real-object4`; `/carousel` as `application/3gpp-mbs-object-manifest+json;version="Rel17"`; all `Cache-Control: max-age=30` [express-mock-media-server/routes/index.js] [express-mock-media-server/app.js].
- tmux: `cp local.env.example local.env` in `scripts/tmux`, edit paths, then `cd scripts/tmux/mbs-function-tutorial` and `bash ./mbs-function-tutorial.sh` (session `mbsf-tutorial`; starts NRF, SCP, SMF, UPF, AMF, MBSTF, MBSF and `npm start` for the mock server; asks for sudo; stop `tmux kill-session -t mbsf-tutorial`) [scripts/tmux/Readme.md] [scripts/tmux/mbs-function-tutorial/mbs-function-tutorial.sh].
**Exercise a feature end to end:** Docker, low-level broadcast: `docker exec -it test_mbs_af_as sendrequest` (POSTs an MBS session, SSM dest 239.0.0.25, `tmgiAllocReq` true, BROADCAST, to `smf-mb-smf.5g-mag.org:80/nmbsmf-mbssession/v1/mbs-sessions`), then in another terminal `docker exec -it ue_with_mbs receivevideo` (joins 239.0.0.25 on `tun_srsue`, plays `rtp://239.0.0.25:9988` with mpv), then `docker exec -it test_mbs_af_as sendvideo` (ffmpeg of the bundled `test.mp4` to `rtp://239.0.0.25:9988`) [mbs-docker-setup/README.md] [mbs-docker-setup/images/test_mbs_af_as/sendrequest] [mbs-docker-setup/images/ue_with_mbs/receivevideo] [mbs-docker-setup/images/test_mbs_af_as/sendvideo].
- User services deployment: `docker exec -it test_mbs_af_as manage-mbs-user-service` creates a user service and an ingest session (POST to `mbsf.5g-mag.org:7777`, source `livesim2.dashif.org`), waits 60 s, deletes the session, waits 30 s, deletes the service [mbs-docker-setup/images/test_mbs_af_as/manage-mbs-user-service].
- What `test/` exercises: `test_user_service_crud` does POST (201 plus Location), PUT (200), GET (200), DELETE (204), then GET 404 on `/nmbsf-mbs-us/v1/mbs-user-services`; `test_ingest_session_crud` creates a user service, POSTs `/nmbsf-mbs-ud-ingest/v1/sessions` (201, state INACTIVE), PUTs state ACTIVE, GETs, DELETEs both, expecting 204 then 404; random ids, cleanup in `finally`; target `[mbsf]` 127.0.0.67:7777 [test/test_mbsf_crud.py] [test/config.toml]. `tests.py`: TMGI allocate (POST `/nmbsmf-tmgi/v1/tmgi` with `{ "tmgiNumber": 1 }`, 200, response schema checked), refresh (second POST, 200, later `expirationTime`), deallocate (DELETE with `tmgi-list` query, 204) against `[mb_smf]` `smf-mb-smf.5g-mag.org:80`; the MBS Session test is a placeholder that GETs `https://www.google.es` and touches no NF [test/MB_SMF/TMGIServiceAPI.py] [test/MB_SMF/MBSSessionServiceAPI.py].
**Fixtures, mocks and sample data:** `test/support/nmbsmf-tmgi/` (request JSON, templates, schemas); `test/config.toml`; `mbs-docker-setup/test/` (own copy, mounted read-only at `/test` in `test_mbs_af_as`, has no `[mbsf]`, no pytest, no `test_mbsf_crud.py`); `mbs-docker-setup/configs/internal/*.yaml`; `mbs-docker-setup/images/test_mbs_af_as/test.mp4`; `express-mock-media-server/public/`; `insomnia/*.yaml`; `scripts/tmux/mbs-function-tutorial/demo-content/dash-if-demo.json`; `scripts/tmux/mbs-broadcast-tutorial/conf/`.
**Logs and how to see that it worked:** Inside containers: `/var/log/open5gs/<nf>.log` (for example `smf_mb-smf.log`, `upf_mb-upf.log`), `/var/log/mbsf.log` at debug level, UE `/tmp/ue_with_mbs.log`, gNB log to stdout [mbs-docker-setup/configs/internal/]. tmux scripts tee each component to `/var/local/log/open5gs/<name>.log` [scripts/tmux/mbs-function-tutorial/mbs-function-tutorial.sh]. Mock server prints Morgan `dev` request lines [express-mock-media-server/app.js]. Success: `sendrequest` prints a JSON response; the UE terminal shows an ASCII rendering of the video; `manage-mbs-user-service` prints `MBS User Service created with id:` and `Deleted MBS User Service:` and exits non-zero on error; pytest and unittest report pass [mbs-docker-setup/README.md] [mbs-docker-setup/images/test_mbs_af_as/manage-mbs-user-service].
**Conventions for contributors:** CLAUDE.md: keep the 5G-MAG Public License (v1.0) header with author and copyright in new files in `test/`; default PR branch is `main`, day-to-day work on `development`; never hardcode `GITHUB_USER` or `GITHUB_TOKEN` in any file, pass them as environment variables; never hardcode personal paths in the tmux scripts, use gitignored `scripts/tmux/local.env`; Python dependencies go in a venv; image versions are pinned in `mbs-docker-setup/.env`; Docker configs live in `configs/<deployment>/` matching `compose-files/<deployment>/` (only `internal` exists) [CLAUDE.md]. Third-party licences are listed in `ATTRIBUTION_NOTICE`. No CONTRIBUTING.md.
