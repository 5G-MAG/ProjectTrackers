## rt-mbs-function
**What it implements:** 5G MBS Function (MBSF), part of the MBS User Services; provides the interface designated Nmb10 in 3GPP TS 29.580 [README.md]. Registers NF services nmbsf-mbs-us and nmbsf-mbs-ud-ingest [src/mbsf/App.cc]; also builds Nmb2 requests to service nmbstf-distsession [src/mbsf/Nmb2Build.cc]. Status "Under Development" [README.md]. Clone checked: main at 2ca01a0 (2026-07-03).
**Language and build system:** C and C++ (`c_std=gnu99`, `cpp_std=gnu++20`), Meson >= 1.4.0, project version 1.1.0; configure fails unless the compiler has `std::chrono::parse` (GCC 14.1+) [meson.build]. Ninja, Java (default-jdk) for the OpenAPI generator [README.md]. Subprojects: open5gs (5G-MAG/open5gs, revision 5mbs, plus patch), freeDiameter r1.5.0, prometheus-client-c, rt-5gc-service-consumers (revision v2.1.x) [subprojects/*.wrap]; rt-common-shared is a git submodule, branch 3GPP-Rel18 [.gitmodules]. Options: `latest_apis` (false), `fiveg_api_approval` ('111'), `fiveg_api_release` ('18') [meson_options.txt].
**Build:** Needs Ubuntu 24.04 or later, GCC 14, working Internet (API files and openapi-generator JAR are fetched at build time) [README.md]:
`sudo add-apt-repository universe` / `sudo apt update` / `sudo python3 -m pip install --upgrade meson` [README.md]
`sudo apt install git ninja-build build-essential flex bison libsctp-dev libgnutls28-dev libgcrypt-dev libssl-dev libidn11-dev libmongoc-dev libbson-dev libyaml-dev libnghttp2-dev libmicrohttpd-dev libcurl4-gnutls-dev libtins-dev libtalloc-dev libpcre2-dev uuid-dev curl wget default-jdk cmake jq util-linux-extra` [README.md]
`git clone --recurse-submodules https://github.com/5G-MAG/rt-mbs-function.git`, then `cd ~/rt-mbs-function`, `meson build`, `ninja -C build` [README.md]. On failure read `build/meson-logs/meson-log.txt`, search `generator-mbsf` [README.md].
The Dockerfile and workflow install more packages than README (libglibmm-2.4-dev, libboost-*-dev, libspdlog-dev, libtinyxml2-dev, libconfig++-dev, libxml2-dev, gcc-14, g++-14, mm-common, python3-pip), point cpp/g++/gcc at the -14 binaries, and install meson with `--break-system-packages` [docker/local/Dockerfile, .github/workflows/build-docker-image.yml]. Container build: `meson setup --prefix /usr --sysconfdir /etc --localstatedir /var build`, `meson compile -C build`, `DESTDIR=/install meson install -C build` [docker/local/Dockerfile].
**Run the unit tests:** README says `meson test -C build regression` (starts an Open5GS NRF and the MBSF, runs regression tests) [README.md]. No test or suite named "regression" exists in the repository, and both `test()` lines in tests/meson.build are commented out, so no test is registered [tests/meson.build]. Framework: none. Run one test: not found in the repository.
**Run it locally:** `cd ~/rt-mbs-function/build`, `sudo meson install --no-rebuild`; start NRF `sudo /usr/local/bin/open5gs-nrfd &`; set the `nrf` section of `/usr/local/etc/open5gs/mbsf.yaml`; `sudo /usr/local/bin/open5gs-mbsfd &` [README.md]. Default config: SBI 127.0.0.67:7777, scp 127.0.0.200:7777, nrf 127.0.0.10:7777, mbsUserServices and mbsUserDataIngestSession 127.0.0.67:7777, `mbsaf` server 127.0.0.67:8888 (comment "MBS-11 (to MBSTF)"), announcements to SSM 232.0.0.1 port 3000 [src/mbsf/mbsf.yaml.in]. Binary is `open5gs-mbsfd` [src/mbsf/meson.build]. Needs an NRF [README.md]. Code also uses an MB-SMF consumer library (`libscmbsmf`) [src/mbsf/meson.build, src/mbsf/MBSMFMBSSession.cc]; README does not say whether an MB-SMF or MBSTF must run.
**Exercise a feature end to end:** README gives no request example and there is no compose file (docker/local has only a Dockerfile and mbsf.yaml.in). Container: image `ghcr.io/5g-mag/mbsf`, entrypoint `/usr/bin/open5gs-mbsfd`, config uses host names `scp`, `nrf`, `mbsf`, listens on 0.0.0.0:7777 and the `mbsaf` server is addr `mbsf` port 8888 [docker/local/mbsf.yaml.in, docker/local/Dockerfile, .github/workflows/build-docker-image.yml]. The handler for `nmbsf-mbs-us` resource `mbs-user-services` accepts POST only with `Content-Type: application/json` [src/mbsf/UserService.cc]. Sample bodies are in tests/json/; `tests/json/change_serv_id.sh <service-id>` writes `*.updated.json` copies with `mbsUserServId` replaced [tests/json/change_serv_id.sh]. Which API each sample targets, and the URL to POST to: not found in the repository.
**Fixtures, mocks and sample data:** tests/json/*.json (15 payloads, e.g. mbs_serv_info.json, qos_req.json, tgt_serv_areas.json; `objIngUri` points at `http://media-origin-server:8080/`); tests/docroot/example1.txt, example2.html and .metadata/example2.html (extra headers `X-Extra-Header`, `Content-Type`) served by tests/test_http_server.cc (listens on port 8000 for 60 s; its build lines are commented out) [tests/].
