## rt-5gms-application-server
Source: shallow clone of branch `main` at 6ab1109 "Increase version number to 1.2.5 (#112)". The submodule `external/rt-common-shared` was not fetched (empty folder). Nothing was built or run.

**What it implements:** 5GMSd Application Server (AS) of the 5G Media Streaming framework (ETSI TS 126.501): M3 configuration service (RESTful, driven by the AF or an M3 client), M2d pull ingest and M4d distribution through an external web proxy daemon that the AS configures and supervises; only Openresty (nginx) is supported [README.md].
**Language and build system:** Python `>=3.7` [pyproject.toml]; setuptools with a custom build backend `backend` in `build_scripts/` that generates the OpenAPI Python classes into `src/rt_5gms_as/openapi_5g` when that folder is missing, via `build_scripts/generate_5gms_as_openapi` [pyproject.toml, build_scripts/backend.py]. The generator needs `wget`, `java` and the submodule `external/rt-common-shared` [README.md, build_scripts/generate_5gms_as_openapi, .gitmodules]. Runtime deps: fastapi, hypercorn, httpx[http2], h11, h2, aiofiles, regex, urllib3, python-dateutil, python-multipart [pyproject.toml]. Entry point `5gms-application-server = rt_5gms_as.app:main` [pyproject.toml].
**Build:**
- `sudo apt install git python3-pip python3-venv`, `sudo python3 -m pip install --upgrade pip build setuptools`, `sudo apt install wget default-jdk` [README.md]
- Install Openresty from its website and put it first on the path: `PATH="/usr/local/openresty/nginx/sbin:$PATH" export PATH` [README.md]
- `cd ~; git clone --recurse-submodules https://github.com/5G-MAG/rt-5gms-application-server.git` [README.md]
- sdist: `cd ~/rt-5gms-application-server` then `python3 -m build --sdist` (result in `dist/`); install with `sudo python3 -m pip install rt-5gms-application-server-<version>.tar.gz` [README.md]
- From source: `sudo python3 -m pip install .`; virtualenv: `python3 -m venv venv` then `venv/bin/python3 -m pip install .` [README.md]. CI uses `python3 -m pip install .` [.github/workflows/build.yml].
**Run the unit tests:** No unit-test framework found: no pytest or unittest anywhere, no test job in CI [pyproject.toml, .github/workflows/build.yml; grep over the repository]. `tests/` holds an M3 client CLI `tests/m3_client_cli.py` (uses `docopt`) and the package `tests/test_m3_client/` (`client.py`) used to drive a running AS by hand. Command to run one test: not found in the repository.
**Run it locally:** `5gms-application-server [-c <configuration-file>]`; `-h` help, `-v` version [README.md, src/rt_5gms_as/app.py]. Without `-c` it reads `~/.rt-5gms/application-server.conf` (non-root only) then `/etc/rt-5gms/application-server.conf`; else built-in defaults [src/rt_5gms_as/context.py]. Defaults: M3 on `localhost:7777`, HTTP port 80, HTTPS port 443, logs in `/var/log/rt-5gms`, caches in `/var/cache/rt-5gms/as`, nginx config `/tmp/rt_5gms_as.conf` [src/rt_5gms_as/context.py]; annotated example `docs/example-application-server.conf`. The default config needs root; first run `systemctl disable --now nginx.service openresty.service` so port 80 is free [README.md]. Needs an M3 client: the 5GMS AF (v1.1.0 or above) or `tests/m3_client_cli.py` [README.md]. systemd unit: `systemd/5gms-application-server.service` (ExecStart `/usr/local/bin/5gms-application-server`) [systemd/].
**Exercise a feature end to end:** README steps for pull-ingest HTTP, quoted as written [tests/examples/README.md] (the README writes `m3_client.cli.py`, but the file is `tests/m3_client_cli.py`):

- `tests/m3_client.cli.py -H localhost:7777 add d54a1fcc-d411-4e32-807b-2c60dbaeaf5f tests/examples/ContentHostingConfiguration_Big-Buck-Bunny_pull-ingest.json`
- Result to check: `http://localhost/m4d/provisioning-session-d54a1fcc-d411-4e32-807b-2c60dbaeaf5f/BigBuckBunny_4s_onDemand_2014_05_09.mpd` should serve the media [tests/examples/README.md].
- HTTPS: `external/rt-common-shared/5gms/scripts/make_self_signed_certs.py tests/examples/ContentHostingConfiguration_Big-Buck-Bunny_pull-ingest_https.json tests/examples/Certificates.json`, then `tests/m3_client.cli.py -c localhost:7777 add testcert1 tests/examples/certificate-1.pem`, then the `-H ... add` command with the `_https.json` file (also `_http_and_https.json`) [tests/examples/README.md].
- Other CLI operations: list, `update`, `delete`, and `purge <provisioning-session-id> [<pattern>]` for `-H`; list/`add`/`update`/`delete` for `-c` [tests/m3_client_cli.py].
