## rt-mbs-transport-function
**What it implements:** 5G MBS Transport Function (MBSTF), part of the MBS User Services; provides the interfaces designated Nmb2, Nmb8 and Nmb9 in 3GPP TS 29.581 V18.5.0 [README.md]. Registers NF service `nmbstf-distsession` [src/mbstf/App.cc]. Status "Under Development" [README.md]. Clone checked: main at fa7b669 (2026-07-03).
**Language and build system:** C and C++ (`c_std=gnu99`, `cpp_std=gnu++20`), Meson >= 1.4.0, project version 1.4.0; configure fails unless the compiler has `std::chrono::parse` (GCC 14.1+) [meson.build]. Also CMake (rt-libflute is a CMake subproject with `BUILD_TESTING=OFF`) [meson.build]; boost >= 1.66.0, uuid, zlib, mpd++ [src/mbstf/meson.build]. Wraps: open5gs (5G-MAG/open5gs, revision bbc-patches), freeDiameter r1.5.0, prometheus-client-c, rt-libflute (revision rt-libflute-0.12.3), libmpdpp (main), libxmlplusplus 5.4.0 [subprojects/*.wrap]. rt-common-shared is a git submodule (branch 3GPP-Rel18) used by the OpenAPI generator [.gitmodules, src/mbstf/generator-mbstf]. Options: `latest_apis` (false), `fiveg_api_approval` ('111'), `fiveg_api_release` ('18') [meson_options.txt].
**Build:** Needs Ubuntu 24.04 or later, GCC 14, working Internet (API files and openapi-generator JAR fetched at build time) [README.md]:
`sudo add-apt-repository universe`, `sudo apt update` [README.md]
`sudo apt install git ninja-build build-essential flex bison libglibmm-2.4-dev libsctp-dev libgnutls28-dev libgcrypt-dev libssl-dev libidn11-dev libmongoc-dev libbson-dev libyaml-dev libnghttp2-dev libmicrohttpd-dev libcurl4-gnutls-dev libtins-dev libtalloc-dev libpcre2-dev libboost-system-dev libboost-thread-dev libboost-program-options-dev libboost-test-dev libspdlog-dev libtinyxml2-dev libconfig++-dev uuid-dev libxml2-dev gcc-14 g++-14 curl wget default-jdk cmake jq util-linux-extra mm-common python3-pip` [README.md]
`sudo sh -c 'for i in cpp g++ gcc gcc-ar gcc-nm gcc-ranlib gcov gcov-dump gcov-tool lto-dump; do rm -f /usr/bin/$i; ln -s $i-14 /usr/bin/$i; done'` then `sudo python3 -m pip install --break-system-packages --upgrade meson` [README.md]
`git clone --recurse-submodules https://github.com/5G-MAG/rt-mbs-transport-function.git`, `cd ~/rt-mbs-transport-function`, `meson build`, `ninja -C build` [README.md]. CI uses `meson setup build --prefix "$PWD/install"`, `ninja -C build`, `meson install -C build --no-rebuild` [.github/workflows/check-build.yml]. Container: `meson setup --prefix /usr --sysconfdir /etc --localstatedir /var build`, `meson compile -C build` [docker/local/Dockerfile]. README text says "5G Data Collection Application Function" and `generator-libspdc` (copy-paste); the script here is `generator-mbstf` [README.md, src/mbstf/generator-mbstf].
**Run the unit tests:** `cd ~/rt-mbs-transport-function` then `meson test -C build --suite rt-mbs-transport-function` [README.md]. Framework: none, hand-written executables registered with `protocol: 'exitcode'`, timeout 600 [tests/meson.build]. Tests in tests/: `test_object_store` (test_ObjectStore.cc; sleeps 10 s, prints Pass/Fail counts but `main` always returns 0) and `test_subscriber_subscription` (test_SubscriberSubscription.cc; 4 cases, returns 1 on error, 77 if all skipped). `test_pull_object_ingester` and `test_object_list_packager` are commented out [tests/meson.build, tests/test_*.cc]. Run ONE test: not found in the repository (names above come from tests/meson.build). CI does not run tests [.github/workflows/check-build.yml].
**Run it locally:** `cd ~/rt-mbs-transport-function/build`, `sudo meson install --no-rebuild`; `sudo /usr/local/bin/open5gs-nrfd &`; set `nrf` in `/usr/local/etc/open5gs/mbstf.yaml`; `sudo /usr/local/bin/open5gs-mbstfd &` [README.md]. Default config: mbstf sbi 127.0.0.59:7777, distSessionAPI 127.0.0.62:7777, rtpIngest and httpPushIngest on 127.0.0.61 port 0 (ephemeral), totalMaxBitRateSoftLimit 1000, nrf 127.0.0.10:7777, SBI TLS off [src/mbstf/mbstf.yaml.in]. Binary is `open5gs-mbstfd` [src/mbstf/meson.build]. Needs an NRF [README.md].
**Exercise a feature end to end:** No README section and no compose file (docker/local has a Dockerfile and mbstf.yaml.in). Container: image `ghcr.io/5g-mag/mbstf`, entrypoint `/usr/bin/open5gs-mbstfd`; its config binds 0.0.0.0 with sbi 7776, distSessionAPI 7777, rtpIngest 6000, httpPushIngest 8000, nrf host `nrf` [docker/local/mbstf.yaml.in, docker/local/Dockerfile]. Request bodies in tests/tutorial/: DistSession-PULL, -PUSH, -DASH-PULL, -DASH-PUSH `-request.json` (each `{"distSession": ...}`, tunnel 127.0.0.7:5678, SSM dest 232.0.0.1:5000). `tests/tutorial/set_tunnel_addr.sh <tunnel-address> <tunnel-port>` (needs `jq`) writes `*.mbsmf.json` copies with `mbUpfTunAddr` replaced [tests/tutorial/set_tunnel_addr.sh]. Packet-mode input: `tests/packet_stream_gen.py [-s BYTES] [-t TTL] [-r PACKET-RATE] [-d] local-address:port destination-address:port [encap-dest-address:port] [encap-src-address:port]` (usage from its argparse, sends UDP) [tests/packet_stream_gen.py]. API is service `nmbstf-distsession`, resource `dist-sessions` (+ `/{distSessionId}/subscriptions`) [src/mbstf/DistributionSession.cc]. Ordered steps and the HTTP call to submit a body: not found in the repository.
**Fixtures, mocks and sample data:** tests/tutorial/*.json, push-croatia-live.mpd (sample DASH manifest), `.gitignore` ignoring `*.mbsmf.json`; DistSession-PULL fetches from `http://127.0.0.1:3004/` (no server for it in the repository) and DistSession-DASH-PULL from `https://livesim2.dashif.org/...` (external) [tests/tutorial/].
