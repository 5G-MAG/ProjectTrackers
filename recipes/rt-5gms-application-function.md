## rt-5gms-application-function
Source: shallow clone of branch `main` at ce8d19e "Increase version number to 1.4.7 (#201)". Nothing was built or run.

**What it implements:** 5GMSd Application Function (AF), a network function of the 5G Media Streaming framework (ETSI TS 126.501); M1d provisioning and M5d client interfaces, built on the Open5GS framework; it also calls the AS at M3 [README.md]. 5G API bindings default to TSG109-Rel17 [meson_options.txt].
**Language and build system:** C (`c_std=gnu89`), Meson `>= 0.63.0` with Ninja [meson.build]; Java (`default-jdk`) and Internet access are needed at build time to fetch the 5G APIs and the openapi-generator JAR [README.md, src/5gmsaf/generator-5gmsaf]. Subprojects (wraps): open5gs fork 5G-MAG/open5gs revision `bbc-patches`, rt-5gc-service-consumers `v1.0.x`, freeDiameter, libtins, usrsctp, prometheus-client-c [subprojects/*.wrap]. Submodule: subprojects/rt-common-shared [.gitmodules].
**Build:**
- `sudo apt update` then `sudo apt install bison build-essential cmake curl default-jdk flex git libbson-dev libcurl4-gnutls-dev libgcrypt-dev libgnutls28-dev libidn11-dev libmicrohttpd-dev libmongoc-dev libnghttp2-dev libpcre2-dev libsctp-dev libssl-dev libtalloc-dev libtins-dev libyaml-dev meson ninja-build python3-aiofiles python3-build python3-h11 python3-h2 python3-httpx python3-openssl python3-pip python3-setuptools python3-venv python3-wheel python3-yaml wget` [README.md]
- `git clone --recurse-submodules https://github.com/5G-MAG/rt-5gms-application-function.git`, `cd rt-5gms-application-function`, `git submodule update` [README.md]
- `meson build` then `ninja -C build` [README.md, .github/workflows/build.yml]. On failure read `build/meson-logs/meson-log.txt` and search for `generator-5gmsaf` [README.md].
- Install: `sudo meson install --no-rebuild -C build`, then `sudo mkdir -p /usr/local/var/log/open5gs/reports` and `sudo chmod -R 777 /usr/local/var/log/open5gs/reports` [README.md].
**Run the unit tests:** Framework: ABTS macros (`abts_suite`, `ABTS_PTR_NOTNULL`, `ABTS_DOUBLE_EQUAL`) from Open5GS `test-common.h` [tests/msaf/tests.c, tests/msaf/pcf-cache-test.c, tests/msaf/utilities-test.c]. Tests are in `tests/msaf/` (pcf-cache, sai-cache, utilities) and are built as executable `test-msaf`, registered with Meson `test('test-msaf', ..., suite: 'app')`, only if the open5gs subproject variable `build_tests` is true [tests/msaf/meson.build, meson.build]. The test runner loads `sample.yaml` [tests/msaf/abts-main.c]. Exact command to run all tests, how to switch `build_tests` on, and how to run ONE test: not found in the repository. CI does not run unit tests [.github/workflows/build.yml]. Some pcf-cache tests contain only comments (stubs) [tests/msaf/pcf-cache-test.c].
**Run it locally:** `/usr/local/bin/open5gs-msafd`; config `/usr/local/etc/open5gs/msaf.yaml`, override with `/usr/local/bin/open5gs-msafd -c alternate-msaf.yaml`; example config `src/5gmsaf/msaf.yaml.in` [README.md]. Needs a running 5GMS Application Server v1.1.2 or above [README.md]. Default addresses (all port 7777): sbi 127.0.0.22, m1 127.0.0.23, m5 127.0.0.24, maf 127.0.0.25; AS entry `canonicalHostname: localhost`, `m3Port: 7777`; `open5gsIntegration: false`; nrf at 127.0.0.10:7777 and bsf listener 127.0.0.99:7779 are configured [src/5gmsaf/msaf.yaml.in]. systemd unit `5gms-application-function.service` starts after the AS service and reloads with HUP [systemd/5gms-application-function.service.in]. Running as a local user without install: only a link to external docs [README.md].
**Exercise a feature end to end:** The README only links to external pages (Testing M1/M3/M5 per version, Postman collection) and to the Docker Compose AF+AS setup in 5G-MAG/rt-5gms-examples `5gms-docker-setup`; the commands are not in this repository [README.md]. Sample payloads: `examples/ContentHostingConfiguration_*_pull-ingest.json` (Elephants-Dream, Llama-Drama, AMP-Samples), `*_https.json.tmpl` and `*_http_and_https.json.tmpl` (replace `@certificate-id@` with a valid certificate id of the provisioning session), `examples/PolicyTemplate-1.json`, `-1b.json`, `-2.json`, `examples/ConsumptionReportingConfiguration.json`; explained in `examples/README.md`. The AF calls the AS at `http://<host>:<m3Port>/3gpp-m3/v1/<component>` [src/5gmsaf/application-server-context.c]; M5 server URLs use `/3gpp-m5/v2/` [src/5gmsaf/service-access-information.c].
**Fixtures, mocks and sample data:** `examples/` (above); `examples/sample.yaml` is the Open5GS-style config used by the tests, with `db_uri: mongodb://localhost/open5gs` and absolute `/home/ubuntu/ogs/...` paths [examples/sample.yaml]. No mock servers in the repository.
**Logs and how to see that it worked:** Logger level `info` by default; optional `logger: file:` line is commented out in the config; default log file location not found in the repository [src/5gmsaf/msaf.yaml.in]. Report data goes to `<prefix>/var/log/open5gs/reports` (`dataCollectionDir`) [src/5gmsaf/msaf.yaml.in, src/5gmsaf/meson.build]. Success lines in the code: `5GMSAF initialize...done` [src/5gmsaf/app.c] and `[<nf-instance-id>] MSAF Running` [src/5gmsaf/msaf-sm.c]. CI only checks that `/usr/local/bin/open5gs-msafd -h` runs after install [.github/workflows/build.yml].
